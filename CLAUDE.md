# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Gateware for a Sipeed Tang Nano 9K (Gowin GW1NR-9C, `GW1NR-LV9QN88PC6/I5`) driving an **ACM9767** DAC module (Analog Devices AD9767, dual 14-bit, 125 MSPS, ±5 V outputs) as a DDS signal generator and SSB / AM / FM modulator (audio streamed from the PC), controlled from a host over the board's FT2232H UART with Modbus RTU. Verilog/SystemVerilog RTL, Icarus simulation, Gowin `gw_sh` for the bitstream, Python for the host side. The build/test harness and the UART + Modbus RTU slave cores were lifted from `~/projects/tang_nano_9K_ov7670` (same author); when in doubt about a harness detail, that repo is the reference.

## Configuration flow (single source of truth)

`platform.json` is the only place clocks, PLL ratio, DAC width, SSB baseband parameters, Modbus id/limits and UART framing are defined. CMake parses it with a regex (keys matched at any depth → **keys must stay globally unique**, the section names are cosmetic) and generates:

- `src/platform_config.vh` — `` `PLATFORM_* `` macros (PLL divider selects, `PLATFORM_DAC_CLK_HZ`, Modbus/UART params). Git-ignored; regenerated on every configure.
- `src/acm9767.sdc` from `src/acm9767.sdc.in` — the `create_generated_clock` multiply/divide for `dac_clk` follows `pll.fbdiv`/`pll.idiv`. Git-ignored. Gowin's SDC parser does **not** accept backslash line continuations; keep each command on one line.

`platform_config.py` is the host-side view of the same file (`DAC_CLK_HZ`, UART framing, Modbus id) used by `scripts/`. The bitstream also reports its sample clock in registers 0x05/0x06 and the CLI prefers that, so a host with a stale `platform.json` still computes correct tuning words.

SSB constants derived by CMake from `ssb.*` and the PLL: `PLATFORM_SSB_INTERP` = dac_clk / audio_rate (**must divide exactly**, fatal otherwise — 54 MHz / 16 kHz = 3375), `PLATFORM_SSB_CIC_SHIFT` = floor(log2(R²)) and `PLATFORM_SSB_GAIN_K` (Q15) = 2^shift / R² so the 3-stage CIC's DC gain R² comes out as exactly unity after the FIR pre-scales by K; `ssb.fifo_depth` must be a power of two, `ssb.hilbert_taps` odd ≤ 255. Change the audio rate or PLL and the Hilbert taps do **not** need regenerating (they are normalised to the audio rate only through the design bandwidth), but re-run `hilbert_generator.py --report` to check the 300 Hz–3.4 kHz flatness.

PLL: `dac_clk = 27 MHz × fbdiv / idiv`, VCO = dac_clk × odiv must stay in 400–1200 MHz (CMake warns). `src/dac_pll.v` is a hand-written rPLL wrapper (not IDE-generated) so it can take the selects from the macros; the static trim parameters mirror what the IDE emits for this device.

## Gowin flow specifics (things that silently break)

- `acm9767_demo.gprj` is the authoritative synthesis source list and is committed as-is (no `.in`). **Register every new synthesizable file there and in `RTL_SOURCES` in `sim/CMakeLists.txt`.** Do NOT list include-only fragments that are not standalone Verilog (`src/sine_lut_init.vh` is a bare list of assignments) — Gowin analyses every listed file on its own and errors out. `acm9767_defs.vh` / `platform_config.vh` are listed because they parse standalone.
- `scripts/gw_run.tcl` sets `set_option -verilog_std sysv2017` (default is Verilog-2001, which rejects `logic`, enums, `$signed` casts in .sv files) and `set_option -use_sspi_as_gpio 1` (header pins 54/55/56 used for the DAC are the SSPI config pins; without this PnR fails with PR2017). It also sets place/route effort 2; override with `PLACE_OPTION` / `ROUTE_OPTION` env vars.
- Gowin resolves `` `include `` relative to the including file's directory, Icarus via `-I src`. All RTL therefore lives **flat in `src/`** so `` `include "timescale.v" `` works in both flows without the `` `ifdef __ICARUS__ `` path dance the template used.
- ROM/RAM init: `dds_channel.sv` initialises `sine_rom` (quarter-wave, depth/4 entries) and `hilbert_fir.sv` its `hilbert_rom` from `initial begin `include "...vh" end` blocks; GowinSynthesis extracts those into pROM (check the synthesis log for `Extracting RAM for identifier`). `hilbert_fir.sv` also zero-fills its delay line in an `initial` loop — keep it: an X in any tap poisons the MAC and then the CIC integrators permanently in simulation (the CIC never forgets an X). Regenerate the .vh files with the scripts when `dac.*` / `ssb.hilbert_taps` change; both are committed and neither is listed in the .gprj.
- Channel count: `platform.json` `dac.channels` (1 today) → CMake emits `` `define PLATFORM_DAC_CH2 `` only for 2; `acm9767_top.v`'s `da2_*` ports, `dds2` and `out2` live under that ifdef, the `da2_*` IO_LOC lines in `src/acm9767.cst` are commented out (uncomment when going to 2 — an IO_LOC for a non-existent port is an error), and the integration testbench wraps its channel-2 checks in the same ifdef. Register 0x07 reports the count; the CLI hides/rejects channel 2 accordingly.
- Header pins: only BANK1/BANK2 (3.3 V) pins may carry DAC signals — the AD9767 needs VIH ≥ 2.1 V; the 1.8 V BANK3 pins 79–86 cannot drive it. Pin table in `doc/wiring.md`; remap by editing `src/acm9767.cst` only. LEDs (10,11,13–16) are active low; the reset button is pin 4, active low, on the 1.8 V bank.

## Architecture

Two clock domains, one crossing:

- **sys_clk 27 MHz** (crystal): `uart` (8-E-1, 1 Mbaud) → `modbus_rtu_slave` (`EXTERNAL_BACKEND=1`, `ADDR_LIMIT=0x180`; the request frame's 7 header bytes are flip-flops, the whole frame also lands in `req_ram` (BSRAM) from which FC10 data is fetched by the `S_WR_FETCH0..2` states with a running byte pointer `fidx` — this replaced a 208 × 8 FF array + adder-indexed mux that was the deepest sys_clk path and ~40 % of the design's flip-flops; the `.sdc.in` carries `report_timing -from_clock/-to_clock` lines so the PnR report lists per-clock worst paths, since the default listing only shows the globally worst clock) → `dac_regs` via the `be_*` handshake (request held until `be_ready`, which `dac_regs` pulses one cycle later with `be_rdata` valid in the same cycle). Writes land in a *staged* bank; a write to `REG_COMMIT` copies staged → committed (`commit_word`, 236 bits = `{ctrl[3:0], ch2[115:0], ch1[115:0]}`, slices via the `` `CH_* `` macros in `acm9767_defs.vh`) and pulses `commit_pulse`.
- **dac_clk** (rPLL, 54 MHz default): `cdc_commit_sync` carries the committed word across with a toggle/ack handshake (word is stable while `s_busy`; `dac_regs` refuses to reload it until the ack returns, keeping a second COMMIT `commit_pending`). `STATUS.bit1` = pending-or-in-flight; the host CLI polls it after every commit. Two `dds_channel` instances (phase accumulator → phase offset → ROM/arith waveform → ×gain → +offset with saturation → offset-binary code, 5-stage pipeline) each feed a `dac_output_stage` (one per channel), which registers the data and forwards `dac_clk` through two ODDRs: WRTx **inverted** (`WRT_INVERT=1`, the AD9767's input-latch edge lands mid-way between data transitions) and CLKx **non-inverted** (`CLK_INVERT=0`, half a period ahead of WRT, clear of the datasheet's forbidden 0–2 ns CLK-after-WRT window whatever the lead skew; costs one sample of DAC latency). Pin 55 = WRT1, 54 = CLK1. Lead-length budget: ±5 ns (±1 m) clock-vs-data at 54 MHz, so signal integrity (≤15 cm unterminated) is the real limit — see `doc/wiring.md`.
- The quarter-wave fold adds two pipeline stages to sin/cos (peak mux, negate); `bb_i`/`bb_q` are delayed two clocks (`bb_i_d1` → `bb_i_d`) to keep the baseband/carrier alignment, so the DAC stream stays bit-identical to the original full-table design shifted by a few samples (verified by diffing loopback dumps). Any further pipelining of sin/cos must add the same delay to the baseband.
- **SSB path** (dac_clk): `async_fifo` (2048 × 16, written from sys_clk by `dac_regs` on any write into the 0x0100–0x017F window, gray-code pointers, `wlevel` → register 0x08) → `ssb_baseband`: a tick every `PLATFORM_SSB_INTERP` clocks pops a sample (on underrun the previous sample is *held* and `underrun_tog` flips; `dac_regs` edge-counts the toggle into register 0x09) → first-order DC blocker (`y = x − x_prev + (1 − 2^-DC_SHIFT)·y_prev`, `ssb.dc_block_shift` 7 → 20 Hz corner, so a held sample decays instead of stepping to zero) → `hilbert_fir` (one time-shared multiplier, TAPS MAC cycles, then ×K gain on both `q` = Hilbert(x) and `i` = x delayed (TAPS−1)/2) → `envelope_limiter` (look-ahead `ssb.limiter_lookahead` = 8 samples, envelope ≈ max(|i|,|q|) + 3/8·min, gain = min(THRESHOLD·2^15 / max window envelope, gain + RELEASE) via a 16-step restoring divider, two DSP multiplies; `ssb.limiter_threshold` 31000 keeps the true envelope < 32768 = the combiner's saturation, `ssb.limiter_release` 32/sample = 64 ms from zero; a run of ≥ 8 underruns followed by data pulses `fade`, restarting the gain from 0 so a resumed stream never starts with a step. Adds 9 audio samples of latency, ~0.6 ms) → two `cic_interp` (3 stages, 44-bit wrap-around integrators, output slice `[SHIFT+15:SHIFT]` saturated) → `bb_i`/`bb_q` at the DAC rate → `dds_channel` waveforms 5/6 compute `bb_i·cos − bb_q·sin` (USB) or `+` (LSB) from the same sine ROM (cos = phase + quarter table) two pipeline stages behind the other waveform sources (harmless: sources are never mixed). Audio latency ≈ FIR group delay (63 samples, 3.9 ms) + limiter look-ahead (8) + CIC (~1.5 samples) + FIFO fill. Why the limiter exists: the SSB envelope √(I²+Q²) of speech runs 1.2–1.5× above the audio peak and the Hilbert transform of a step (a recording that starts on a DC offset, or a stream that stops) overshoots by 4×, so host-side peak scaling cannot prevent the combiner from saturating; the 2026-09-15 bench capture showed exactly that as periodic harmonic bursts. Both channels see the same baseband. Waveform 7 (AM) multiplies `cos` by `32768 + (bb_i·modparam)>>16` and halves the result (carrier at half scale, 100 % depth peaks at full scale); waveform 8 (FM) adds `(bb_i·modparam)>>7` to the phase increment every clock (deviation at full-scale audio = modparam·256 FTW units) and outputs the plain sine. `bb_i·modparam` is one shared multiplier (`mod_prod`).
- Resets: `reset_sync` (async assert / sync release) per domain; the dac domain is held in reset until `pll_lock`. PLL lock is 2-FF-synced back into sys_clk for `STATUS.bit0` and LED0.
- SDC declares `base` and `dac_clk` as asynchronous clock groups; the only crossings are the 2-FF toggle synchronisers, so no set_false_path per net is needed.

Semantics worth remembering: a disabled channel drives mid-scale `0x2000` (≈ 0 V on the module's bipolar output) and resets its phase accumulator; `AMPLITUDE` gain is `(v+1)/65536` so `0xFFFF` is exact unity; `OFFSET` is signed DAC LSBs and saturates; the per-channel `invert` bit XORs the code (the module's analogue polarity is not documented — flip this from the host rather than rebuilding). `f_out = FTW × f_dac / 2^32`.

Spurious-free range: the sine ROM is a 4096-point table (`dac.sine_lut_depth`) stored as its first quadrant only (1024 × 14 bits, one BSRAM per read port, so 2 per channel for sin + cos); `dds_channel.sv` folds the other quadrants by index mirroring/negation and inserts the exact ±8191 peaks at the quarter points, bit-identical to a full table (`sim/unit/dds_channel/sine_table.sv` proves it for every point). Indexed by the top 12 phase bits, so phase-truncation spurs sit near −72 dBc for any carrier. Loopback at 7 MHz USB (7 tones 300–2600 Hz, level 0.5, before the limiter): steady-state SNR 71.6 dB, unwanted sideband 74.6 dB, carrier 65.5 dB; the ctest cases run at level 0.8 where the limiter is active (envelope 1.1) and give 68.4 / 81.5 / 47.7 dB with 0 clipped codes (the gain modulation costs carrier suppression, the price of not clipping) — the same as at f_dac/32, i.e. no carrier-frequency dependence left (the 1024-entry table gave 60.5 / 60.7 dB at 7 MHz). The loopback's overall `snr_eq_db` is lower (~53 dB) only because the 5 ms fade edges of the test audio contain sub-200 Hz energy below the Hilbert transformer's passband; `snr_steady_db` is the in-band figure. Multi-tone SSB has an envelope up to ~1.4× the audio peak: keep the audio level ≤ 0.6 of full scale or the DAC clips (the script counts clipped codes).

Timing headroom: dac_clk closes at ~84 MHz with every path ≤4 LUT levels: the SSB combiner (31-bit add/sub) is registered before saturation, the DC-offset add before saturation/code, the ROM fold's peak mux before its negate, and the FIR delay-line write address is precomputed (`wr_next`). The 44-bit CIC integrators are carry chains, not LUT levels. Raising `pll.fbdiv` beyond ~75 MHz dac_clk would first hit the multiplier-to-register paths (DSP outputs); base (27 MHz) closes at ~67 MHz with ≤6 logic levels and >22 ns slack everywhere: `modbus_rtu_slave` uses a parallel-form CRC-16 (`crc16_update` is 16 XOR reductions over fixed masks, derived from the shift/xor definition — regenerate the masks the same way if the polynomial ever changes) and absorbs each TX byte into the CRC one state after the byte mux (`tx_crc_en` in `S_TX_PEND`); `dac_regs` decodes addresses by bit slicing (channel blocks must stay at 0x10/0x20, audio window at 0x100–0x17F); `async_fifo` registers its level readout in two stages. Going lower would need a registered accept in `dac_regs` (one more cycle per Modbus register access) for one or two levels — not worth it.

## Testing conventions

- Testbenches: `sim/unit/<dut>/<scenario>.sv`, `sim/integration/<topic>/<scenario>.sv`, registered in `UNIT_TESTS` / `INTEGRATION_TESTS` in `sim/CMakeLists.txt` (each becomes `<scope>_<dut>_<scenario>_{BUILD,SIM,run}`). Every testbench is compiled with the full `RTL_SOURCES` list plus the Gowin simlib (`-s main -s GSR` roots), so no per-test source lists.
- Boilerplate: `` `include "test_config.sv" `` (generated: `DEFAULT_LOG_LEVEL`, `ENABLE_DUMPVARS`), log through `DataLogger` (`svlogger.sv`), finish with `` `TEST_PASS `` / `` `TEST_FAIL `` from `test_utils.sv` (sets the exit code the runner checks), and a watchdog `always #N` / `initial #N` that fails the test.
- RTL uses `` `WRAP_SIM(#1) `` on every NBA, so testbenches sample with `@(posedge clk); #2;` to avoid racing the NBA.
- Verilog signedness trap (bit us on 2026-09-15): a concatenation such as `{{2{x[15]}}, x}` is *unsigned* and makes the whole expression unsigned, so a `>>>` in the same expression becomes a logical shift for negative values. Sign-extend through `wire signed` intermediates (see the DC blocker in `ssb_baseband.sv`) and make unit tests exercise negative values — the first `dcblock.sv` only used positive steps and passed while the sideband test collapsed to 15 dB.
- Anything in front of `cic_interp` must have *constant* latency from strobe to strobe: the interpolator integrates each comb output for exactly R clocks and a jittering strobe leaves a permanent DC residue in the integrators (`envelope_limiter` always runs its 16 divider steps for that reason).
- `sim/integration/top/modbus_to_dac.sv` runs the real `acm9767_top` with the real `platform.json` values (27 MHz, 1 Mbaud, rPLL model — lock takes ~50 µs sim time) and a second `uart` instance as the host; it samples `da*_data` on `dut.dac_clk`. When checking the ODDR-forwarded clocks count edges with an `always @(da1_clk)` counter — sampling once per `dac_clk` always sees the same phase.
- SSB quality is proven by `sim/unit/ssb_baseband/sideband.sv`: real platform constants, a 2 kHz tone through a TB FIFO model into `ssb_baseband` + `dds_channel`, Hann-windowed Goertzel filters at fc±fm and fc over a 2 ms window; passes at ≥35 dB (measures ~84 dB). It needs ≥140 audio samples of fill (127-tap FIR + CIC) before measuring — 8 s of iverilog. `sim/integration/top/ssb_stream.sv` covers the Modbus plumbing (FIFO window via FC10, LEVEL, UNDERRUNS, drain) and takes ~40 s.
- Unit tests for the front end: `ssb_baseband/limiter.sv` (exact pass-through with the look-ahead delay, a 46340-envelope hit limited to < 32768 with the gain already down on the preceding samples, release rate, fade ramp) and `ssb_baseband/dcblock.sv` (DC step decays with τ = 2^shift, an outage never steps the FIR input, one fade pulse on resume, none for a 3-sample hiccup; ~50 s). `sideband.sv` fills 160 samples before measuring (FIR + look-ahead + DC block).
- Loopback: `sim/unit/ssb_baseband/loopback.sv` is a *file-driven* run (plusargs `+in/+n/+out/+ftw/+wave/+modparam`, int16/uint16 big-endian), compiled by `register_sim_tool` (build-only, no ctest of its own) and driven by `scripts/ssb_loopback.py`, which generates faded multi-tone audio (or a WAV), pads it with silence so the FIR/CIC start and end in a defined state, runs `vvp`, then demodulates with numpy: FFT analytic signal → ×e^(−jωc n) → 5 kHz low-pass (SSB, compared as *complex* analytic signals with a fitted complex gain because the demodulator's carrier phase is arbitrary), envelope (AM), or instantaneous frequency (FM); alignment by cross-correlation at the DAC rate; SNR reported raw and with the CIC sinc³ droop equalised (the chain matches that model to 0.01 dB per tone); the reference is first passed through the modulator's DC blocker model (`--dc-shift`, default from `platform.json`), without which the test tones' fade edges would score ~30 dB worse. The loopback FIFO model never underruns, so the limiter's fade is not exercised there. Spectral metrics use the steady-state middle of the RF dump. Thresholds live in `THRESHOLDS`; the four ctest cases are registered only when python3 + numpy exist.
- Host side: `scripts/tests/test_acm9767_ctl.py` drives the CLI (`main(argv, transport=...)`) against `FakeSlave`, which models the register semantics (staged/committed, RO regs, waveform mask, exceptions). Extend it when the register map changes; keep `acm9767_ctl.py`'s register constants in sync with `src/acm9767_defs.vh` (there is no shared generator for those).

## Hardware status

Verified on the board (2026-09-05): programming via `hw_program`, Modbus over `/dev/ttyGowin` (identity, PLL lock reported, staged writes + COMMIT + read-back on both channels, illegal-address exception), defaults restored after reprogramming. A single timeout on the very first request after programming was seen once and never reproduced across 14 later attempts.

The SSB/AM/FM bitstream (2026-09-06 build) was loaded into SRAM on 2026-09-15: identity, version, PLL lock, 54 MHz, 1 channel all read back over Modbus. `UNDERRUNS` reads 65535 at idle because the SSB tick pops the empty FIFO continuously and the counter saturates — clear it after streaming starts, it is meaningless before. The SSB stream was exercised the same day: `stream --carrier 7.1e6 --mode usb --tone 1000 --seconds 10 --level 0.5` kept the FIFO at ~1900/2048 for 10 s with 56 underruns at start-up (the tick pops the empty FIFO until the first block lands) and none mid-stream; the counter keeps rising after the stream ends while the channel stays enabled. Analogue output still unscoped. The embedded flash is **erased/invalid** (a `--run 5` was killed during the erase on 2026-09-15): the board does not boot on its own until `hw_program_flash` (or `--run 5`) is run to completion.

Programmer quirks (`programmer_cli` 1.9.12.02): `--run 6` (flash) spent 4 min in "Programing" and then sat at "Verifying 0 %" for >8 min twice; use `--run 5` (no verify) or be patient. `--run 2` (SRAM) once ran >3.5 min without finishing and, after a hard kill, completed in 5.3 s on the next attempt. The tool ignores SIGTERM — stop it with `pkill -9 -x programmer_cli`. Its progress output uses `\r` without newlines, so when piping run it under `stdbuf -o0` and `tr '\r' '\n'`, or nothing appears until it exits. Only one programmer can hold the FT2232 at a time, and an interrupted SRAM load leaves the FPGA unconfigured (Modbus times out) until the next successful load or a power cycle.

**Analogue path, first look (2026-09-15, TinySA Ultra on the module output, /dev/ttyACM0, fundamental reads -28 dBm at half scale so there is ~45 dB of attenuation/coupling in the user's path):** the chain distorts. Plain 7.1 MHz sine: H2 -25 dBc / H3 -28 dBc at amp 0.5, H2 -18 dBc at amp 1.0, clean (-47/-51) at amp 0.25; identical with 0/10/20 dB analyser attenuation (not the TinySA); absent at 1 MHz (H2 -47), -34 at 3 MHz; strongly DC-offset dependent at fixed amplitude (amp 0.25: offset 0 clean, +0.25 -> H2 -25 dBc); unchanged with dac_clk 24 MHz (rebuild with pll 8/9/32, so **not** DAC latch timing/wiring skew); bit-exact RTL in sim rules out the digital path. A fine offset sweep at amp 0.125 (+-1023 LSB) is clean (H2 <= -45 dBc) at every centre code 0x2000..0x3000, so it is not a narrow bad-code region: the distortion needs a large swing *and* positive excursion (amp 0.25 at 0x2000..0x3000 bad, at 0x1800..0x2800 clean), i.e. a level- and slew-dependent limit in the module's analogue output stage / its load not the FPGA, the DAC data path or the TinySA. The user's path is module -> 40 dB pad -> TinySA (50 ohm): -34 dBm at amp 0.25 = +6 dBm (~1.3 Vpp) at the module, i.e. ~+-2.5 V full scale into 50 ohm (an op-amp with a 50 ohm series resistor) — full scale would need ~100 mA peak at 7 MHz, which is the op-amp's current limit. Fix by loading it lighter (series R of a few hundred ohm), a 50 ohm buffer, or keeping `amp` <= 0.25 (harmonics >= 46 dB down confirmed by the user); the SSB envelope must stay inside the same limit (`--level` <= ~0.15 for the hot voice WAVs). `scripts/` has no TinySA tooling; the ad-hoc probes used `scan <f0> <f1> 450 3` over pyserial at 115200 (the firmware prints an occasional malformed float, parse tolerantly).

The periodic SSB "harmonic bursts" seen while looping a voice WAV were the modulator saturating: the recording (`~/Downloads/tx_20260903_131258.wav`) peaks at 1.0 FS, has a -0.105 FS DC offset and starts with a step; its analytic (SSB) envelope reaches 4.2x the sample peak, so at `--level 0.6` the combiner clips for the first seconds of every pass. `acm9767_ctl.py stream` scales by sample peak, not envelope, and does not remove DC — worth fixing (DC removal, envelope-based level, soft limiter).

**Still unverified**: the analogue path beyond the above. No ACM9767 was wired/scoped, and the module's own header pinout and polarity were not available (only the AD9767 datasheet was); `doc/wiring.md` assumes `DA1_D[13:0]/DA1_CLK`, `DA2_D[13:0]/DA2_CLK` naming with WRT tied to CLK, 3.3 V logic and a 5 V supply. Check those against the module manual before wiring, and use the `invert` bit if a sawtooth ramps the wrong way.

## Tiny Tapeout port (`tt/`)

`tt/` is a self-contained Tiny Tapeout (IHP SG13G2) project generated from the `ttihp-verilog-template`: plain Verilog-2005 RTL in `tt/src/`, cocotb tests in `tt/test/` (own venv: `tt/.venv`, `cd tt/test && PATH=$PWD/../.venv/bin:$PATH make`), `tt/info.yaml` + `tt/docs/info.md` for the datasheet. It shares nothing with the FPGA sources except the register map and the host CLI; do not `include` across the two trees.

- `SSB` top parameter (default 1, submitted on **8×4 tiles** = 32 tiles, 48.5 % utilisation; `info.yaml` says 8x4, which the TT validator rejects until the TT team enables the size — fall back to `SSB=0` + `tiles: "8x2"` (54 %) if they do not): 1 adds a phasing-method SSB modulator (`baseband_dsp.v` HILBERT chains → `cic_interp.v` ×2 → mixer in `dds_channel.v` on `sine_interp`'s cosine output), verified at 57.5 dB sideband / 54.7 dB SNR with `scripts/ssb_loopback.py --fs-dac 50e6 --audio-rate 16000 --max-delay 40 --dc-shift 0 --allpass 0.4058,-0.5403,-0.8822` (`--dc-shift 0`: the tt build has no DC blocker; the script models the FPGA's by default) on `tt/test/tb_loopback.v` — but it is 282 k µm² (98 % of 8x2), so it cannot be taped out on TT as is. `make SSB=1` in `tt/test` runs cocotb on it. The all-pass poles came from differential evolution over 250–3600 Hz (3+3 sections, 0.21° max error); more sections did *not* help the optimiser. `serial_mul.v`'s product is valid on the same clock `done` rises (the accumulator is the output) — a registered copy one clock later made every sequencer step consume the previous product, which showed up as ~9 dB sideband suppression.
- No RAM/PLL/DSP: the sample clock is the TT clock (`CLK_HZ` parameter, 50 MHz), sine comes from `sine_interp.v` (64-entry midpoint quarter table + linear interpolation, ±1 LSB, `tt/test/test_sine.py` sweeps all 65536 phases — keep it passing), AM/FM products go through `serial_mul.v` (one shared 17×17 shift-add multiplier after each audio tick) so only `raw × scale` is a parallel multiplier. SSB is not ported.
- Modbus slave is a flip-flop version (`MAX_FRAME` 24 → FC16 of ≤ 7 registers, `MAX_QTY` 4 for FC03); the CRC masks must be the verified parallel form (copy from the FPGA `modbus_rtu_slave.sv`, do not retype).
- Area: measure with yosys + the SG13G2 liberty (`abc -liberty`, `dfflibmap -liberty`, `stat -liberty`; the .lib is downloadable from IHP-Open-PDK, not committed). Last: SSB=1 280 k µm² (17.3 k cells, 2.5 k FFs, 44 % of the area is flip-flops), SSB=0 156 k µm². A reset flip-flop is 52.6 µm², so flip-flops dominate: every 16-bit register costs ~840 µm².
- cocotb timing traps: at 16 kS/s the 16-deep FIFO is 1 ms; a Modbus frame is 100–340 µs on the wire, so clear underruns *after* a push and never expect the level to equal the count pushed.

### Timing and the physical flow

- Pre-layout timing (yosys `abc -liberty ... -D 20000` on the SG13G2 typical liberty): longest register-to-register path 5.4 ns against the 20 ns clock, gate delays only. Post-route STA (with wires, clock tree, hold fixes, all corners) comes only from LibreLane/OpenROAD: the TT GitHub action, or locally via `pip install librelane` + `docker pull ghcr.io/librelane/librelane:<ver>` + the IHP PDK via `ciel` — that is 4–6 GB of disk, and **this machine's root disk is a 233 GB drive at ~98 %**; a container pull filled it on 2026-09-08 and silently truncated files being written. Check `df -h /` before pulling anything large.
- **Never run `rm -rf <relative path>`**: the Bash tool's working directory is reset between commands, and on 2026-09-08 an `rm -rf tt` meant for the scratch directory deleted the whole `tt/` subproject (nothing was committed). Use absolute paths for anything destructive, and commit early.
